# 规格、价格可信度与多媒体分析升级设计

日期：2026-10-26

基线：`f728ff8` / v0.1.1
状态：设计待用户批准；尚未开始实现。

## 1. 目标与已确认范围

用户确认采用方案 A：分阶段实施，完成规格与价格可信度、多媒体分析，再进行全项目检查、性能优化及缺陷修复。
重点是同一商品链接中的型号／容量组合，以及“标价不代表实际售价、需要询价”的商品。
继续沿用 Python、FastAPI、SQLAlchemy、SQLite、Playwright、Jinja2/HTMX，保留 uv/Conda 与 Docker 运行方式。

核心原则：先确认选项、价格及证据，再判断预算与性价比。未知不是零元，提取失败不是没有瑕疵。

非目标：自动询价、自动聊天、下单或支付；绕过登录／验证码／访问控制；穷举商家全部 SKU；
音轨理解和完整动态故障诊断；宣称兼容未经验证的所有闲鱼页面；重写前端或引入分布式服务。

## 2. 方案比较与选择

- A（用户选择）：分阶段建立规格／价格基础，再接入媒体证据，最后测量并优化。每阶段可测试、审查、回退。
- B（不采用）：同时替换全部抓取、数据和分析逻辑，末尾统一测试。集成风险大，难以定位回归。
- 技术实现采用结构化页面证据优先、确定性规则裁决，LLM 只辅助抽取文本声明与总结，不生成实际售价或虚构 SKU。
  全靠 LLM 推断型号和价格不能提供可核对证据；一开始绑定某一家原生视频 API 则限制现有模型兼容性。

## 3. 当前实现与必要改变

- `ListingData/ListingDetail/Listing` 只有图片列表，没有视频媒体契约；品相请求最多发送四张图片。
- `variants` 仅由价格区间生成“最低价／最高价”，不是真实可购买组合。
- 搜索标价在详情提取前就被预算过滤；它还用于价格走势、性价比、重推，可能错误比较不同规格。
- `_fetch_detail` 通常有描述就不刷新；现有商品重评未必更新规格与媒体。
- 网络、模型调用处于较长数据库会话内；需测量锁占用、浏览器启动、重复模型请求与关系查询次数。
- “重新上架”判断发生在 status 被设为 active 之后，是需以回归测试验证的疑点；有限搜索结果未见不等于已下架。
- 当前应用无用户认证。升级不扩大默认网络暴露范围，不借此次改造冒充解决多用户安全问题。

## 4. 阶段一：规格与价格可信度

### 4.1 数据与职责

沿用按任务隔离的 Listing 父记录；保留 `Listing.price` 与旧 PriceSnapshot 为“页面标价／旧标价走势”，
不再把它们直接当作目标规格的成交价。新增规范化的选项和观察记录，不继续向无类型 variants 字典塞业务状态。

- WatchTask：新增独立的目标规格文本 `target_variant`（如“iPhone 15 / 256GB / 非扩容”）和 `notify_pending_price`。
- ListingOffer：`listing_id`、稳定 `offer_key`、原站 SKU ID（如存在）、规范化属性、选项名称、可用状态、
  当前价格状态／证据、匹配状态、评估结果。唯一约束 `(listing_id, offer_key)`。
- OfferObservation：关联 offer、原始来源、价格状态、确定价或区间、采集时间、页面位置／原文片段、内容指纹。
  新价格以人民币分整数保存；原始金额用 Decimal 校验后转换，拒绝负数、非有限值和不支持的币种。
- ManualQuote：关联 offer、金额、用户说明、确认／失效时间、撤销状态；独立于抓取值，绝不被爬虫覆盖。
- offer 维度的评估与通知记录：记录使用的 observation/quote、媒体证据和任务条件指纹；通知增加 offer 与事件类型引用。

原站 SKU ID 优先作为身份；无 ID 时按完整规范化属性组合生成稳定键，不依赖显示顺序或价格。
多个不同选项出现相同属性键、或无法确认组合完整性时标记歧义，不把它们合并。
普通单件无规格商品使用默认 offer；旧 variants 区间仍展示为历史信息，不能迁移为真实 SKU。
父 Listing 的摘要兼容旧 API，但新增明确的有效价格／规格／状态字段，前端不得再将旧 price 标成确认价。

### 4.2 价格状态与裁决

| 状态 | 含义 | 允许预算判断与性价比排名 |
| --- | --- | --- |
| exact | 当前具体可用选项有明确价格，且无适用的冲突或非售价声明 | 是 |
| range_or_from | 仅起售价或区间，目标选项未确定 | 否 |
| inquiry | 明示需咨询、标价非售价或占位价 | 否 |
| conflict | 同一选项同时存在互斥的价格声明 | 否 |
| unknown | 抓取失败、信息缺失或映射不明 | 否 |

另有“人工确认报价”来源，不将它伪装为原站 exact。exact 仅表示页面证据明确，不保证卖家最终履约价。
stock 状态使用 available/unavailable/unknown；SKU 不可用时不参与正常推荐，未知库存明确展示。
“起”本身不能推断高价规格售价；“优惠私聊”与“所有标价非实际售价”区分作用范围；
声明作用范围不清时保守待确认，不能让一个疑似数字覆盖其他明确证据。
来自图片或 LLM 的识别仅为待核对声明：必须关联证据，不独立提升为 exact。

### 4.3 采集与目标匹配

首先从商品所属 DOM／结构化页面状态读取真实 SKU 组合；只读必要的选项交互，不点击购买／咨询／支付。
支持的结构化状态格式需要真实样本验证，不预先假定平台存在某个 API。
最多处理每链接 20 个候选组合，只针对目标匹配选项做后续昂贵分析；限制截断时显示“规格获取不完整”。
规则负责型号、容量等可确定约束；LLM 可以提出映射候选，但不能把不确定候选标为已匹配。
没有填写 target_variant 时，普通单件照常处理；多规格商品显示已核对的选项，多个匹配项分别评估，不能默认最低价代表整件。
明确型号／容量不匹配不推送；目标匹配不确定则留待确认，不进正常排名。

搜索阶段只保留非价格的安全过滤与抓取数量上限。预算过滤在 offer 解析后进行，避免起售价提前漏掉目标规格。
默认每任务每轮最多 30 个详情候选；超过预算进入后续轮次的有界待抓取队列（持久化或可重建），记录未处理数量，不能静默当作不匹配。
明确要求规格核验而 fetch_detail 关闭时，保留待确认状态并提示该设置不能获得确价，不偷偷启用详情抓取。
exact 的单价落在任务预算内才进入正常候选；待确认价不以标价判断超预算，不进入性价比模型／本批最优。
已知品牌或商家身份不作为直接排除条件；包装、配件、整机作为不同选项匹配，避免交叉借用证据。

### 4.4 人工报价与通知（下列默认值为本设计提议）

- 待询价商品默认站内保留，独立的待确认提醒开关默认关闭，避免升级后突然增加外部通知；用户可按任务开启。
- 手动报价必须绑定明确规格；确认页面同时展示最新抓取的价格证据，默认有效期 7 天，可修改或撤销。
- 人工报价有效且规格匹配时可用于预算和排名，所有结果注明“人工报价”和确认时间。
  新抓取的同 SKU 价格／非售价声明有实质变化时，旧报价转为需复核；选项不可用或身份歧义也会使报价不可用于推荐。
- 当人工报价与页面 exact 同时有效，优先采用用户对照最新页面证据确认的人工报价（人工操作页明确提示该优先级）；
  该报价必须记录确认时的页面证据指纹。若页面证据实质变化，先暂停人工报价而不是偷偷切回页面价继续推送。
  用户复核或撤销后才重新确定有效来源。页面价与人工报价的历史分开比较；两种来源切换仅称“价格来源更新”，
  不标为降价，同来源内的新价格与旧价格可比时才计算降幅。人工报价到期后可采用仍新鲜的页面 exact，注明来源切换。
- 不同规格分别做同价历史比较；从 A 切换到 B 不能叫“降价”。历史证据保留，不覆盖。
- 预算、规格或关键需求修改使评估失效；重评不沿用旧目标报价，不复用旧任务条件的评分。
- 通知以 offer、事件类型、证据／评估版本、渠道记录状态；待确认转明确可触发一次正常提醒。
  相同待确认状态与证据不重复推送；渠道失败单独记录，不将其他成功渠道重新发送。
  不声称网络超时情况下能严格 exactly-once；无幂等接口的渠道需提示可能重复，避免无限重试。
- 未知价格只展示需求和媒体分析的独立结果，不产生可与正常候选混排的综合性价比名次。

### 4.5 刷新与页面行为

任务表单、API、设置、列表、详情和通知统一使用价格解析服务输出；不在模板另写价格裁决。
详情提供规格明细、页面标价与有效价格的区分、原文依据、人工报价的新增／撤销操作。
普通列表仅将确价候选纳入默认性价比排序；待确认独立筛选，预算／价格排序不拿占位价填空。
SKU 与有效价格最多缓存一个调度间隔，手动重新分析和刷新强制更新；人工报价独立保持。
下次抓取失败不抹除旧证据，但将其标为旧观察，不把该轮故障视为库存变化或降价。
价格、规格映射与可用状态的核验有效期为一个任务调度间隔，自最后成功核验的时间计算；
短暂失败不提前缩短这个有效期，但该失败本身不产生新的价格事件或提醒。
任一必要证据到期后，该 offer 转为待复核并暂停正常排名与正常外部提醒，不删历史记录、不重新认定售罄。
人工报价的七天有效期只描述报价本身，不能代替新鲜的规格／可用状态证据；暂停推荐不会撤销或缩短报价期限，
后续成功核验无实质变化时可在原有效期内恢复。恢复不凭状态变化重复发送已成功的事件。

## 5. 阶段二：视频及图文混合证据

### 5.1 媒体契约

MediaAsset 记录 listing/可选 offer、image/video/frame 类型、原始来源／页面位置、封面、时间位置、内容 hash、
采集时间、父视频引用、处理状态与失败原因。没有确切 SKU 关联时标记 listing_shared，不假设属于任意一台机器。
只采集商品详情主媒体区域，排除推荐流、头像、广告；不能只按整个网页的 video/img 标签抓取。
视频 URL 可能过期、blob 或为分段流：首版支持可授权获取的直接 HTTP(S) 媒体；blob/DRM/未适配流清楚标注不支持，
不绕过权限。必要时通过正常页面刷新重新获取临时 URL。

### 5.2 抽帧与资源边界（设计默认值，可配置）

使用 FFmpeg/ffprobe 子进程处理本地受限文件，再把帧转为现有视觉接口支持的图片输入；不要求特定厂商的原生视频 API。
Docker 显式安装 FFmpeg；uv/Conda 检测外部工具，缺失时禁用视频处理并提示安装，不让应用无法启动。
视频分析为明确开关，默认关闭且显示“未分析视频”；启用后与图片联合分析。每商品最多 1 个视频、8 张原图、6 帧，
每次模型请求总视觉输入最多 8 张（有视频时优先最多 4 张原图 + 最多 4 帧，其余作为详情证据保存）。
视频上限 100 MiB、180 秒；流式下载最多 60 秒、解码最多 30 秒，超预算中止并删除半成品；媒体处理并发 1。
有限采样覆盖起、中、末，过滤模糊／重复帧；不宣称未采样片段已检查，也不对音频或动态故障下确定结论。
下载器验证 URL、DNS 解析地址和每次重定向；禁止回环、内网、链路本地、云 metadata 等目标。
媒体下载与可配置内网模型地址是不同信任边界；不用媒体请求携带任意域 Cookie。子进程不经 shell，
FFmpeg 仅读本地输入、限制网络协议和执行时间；文件输出在受控缓存根目录内。

### 5.3 缓存与证据分析

缓存位于 data/media-cache，默认上限 1 GiB、保留 7 天；原视频成功抽帧后删除，失败半成品立即清理。
按内容 hash／处理参数去重，媒体 URL 改变不直接认定内容改变；无法取得内容时不可凭 URL 缓存成成功。
已被分析引用的帧若因容量被清理，保留摘要、hash、时间位置并显示“证据文件已清理”；可重新获取，不显示坏链接。
API 不接受任意本地路径；媒体通过受控 ID 映射提供，不泄露签名 URL 的令牌、Cookie 和宿主文件路径。
模型请求使用可验证的 data URL 或受支持上传，不把容器本地文件路径传给远程模型；现有 chat/responses 两接口都要覆盖测试。
分析输出包括证据 ID、来源、视频时间位置、观察到的瑕疵、卖家声明、信息冲突和未验证项。
结构化校验只允许引用本次输入的证据 ID；拒绝模型虚构的帧、价格、容量或来源。
共享媒体不能自动生成某一 SKU 的确定品相结论；分析结果保留样品／不保证对应实物提示。
抓帧或模型失败时保留可用图片分析；无有效视觉证据时不生成“品相达标”结论，正常提醒明确标识未核验。
最低品相分是明确门槛：任务设置大于 0 时，必须有适用于该 offer 的有效视觉评分达到门槛，
未分析、分析失败、只有不确定关联的共享样品媒体均进入待核验，不参与正常排名或正常外部提醒。
最低分为 0 时，确价且规格匹配的商品可在明确标注“品相未核验”的情况下按价格等已知信息排名／提醒，
但不能生成品相通过结论。媒体与文字有实质冲突时保留冲突状态，不能用缺失分数的默认半分掩盖。
关闭视觉而任务最低分大于 0 时提示配置冲突，不能静默放行或修改用户门槛；这是相对于旧放行逻辑的有意行为改变。
评估缓存包含证据内容、任务条件、模型／提示词版本；变更时失效。支持手动强制重评，避免陈旧结论。

## 6. 阶段三：全项目检查、性能与缺陷修复

先建立可重复的基线，再按实测瓶颈修复；不承诺“没有任何 bug”或给出未测量的提速比例。

- 正确性：重新上架、有效价格变化、规格售罄、部分解析失败、重评、暂停／删除任务、通知失败恢复。
- 生命周期：有限搜索结果未见只能称“本轮未见／疑似不可用”；只有详情确证下架才标为确定下架。
- 数据库：外部请求不占写事务；按商品／步骤短事务，迁移失败不留下半套新结构；验证并发读写与 N+1。
- 浏览器：评估单轮复用浏览器／隔离上下文，取消／异常可靠关闭，不跨任务泄露 Cookie 或页面状态；保留串行任务限速。
- 模型：同证据不重复分析；有限超时、退避、重试与单任务调用预算；预算耗尽保留待处理状态，不误报否定。
- 可观测性：每轮记录候选数、详情耗时、媒体耗时、LLM 次数、缓存命中、SQL 次数和失败状态；日志屏蔽秘密。
- 安全回归：表单先校验后提交、敏感配置与运行时配置边界、媒体下载边界、noVNC 默认关闭、路径穿越。

用固定的合成／脱敏商品集和 mock 网络／模型做可重复基准，比较冷启动与第二轮热缓存：
热缓存不重复启动每商品浏览器、不重复相同媒体的模型分析；记录中位数与 P95、查询数、调用数和资源峰值。
任何优化需证明结果一致、无重复通知、无明显回归；绝不为性能提高抓取频率或取消安全等待。

## 7. 迁移、兼容与回退

开发和 Docker 验证使用独立数据库、缓存、容器名和未占用的回环端口，禁止挂载生产 data/；默认禁用真实通知与定时任务。
生产升级前停写并制作可恢复备份；迁移按版本、幂等、事务执行，先验证临时旧库副本，不能运行未备份的破坏性迁移。
新增表与字段保留原数据；旧评分标记 legacy_unverified，不转换为新规格的确定结论；原有通知历史不触发重发。
旧任务 target_variant 为空、待询价外部通知关闭；旧单件下次成功详情抓取后生成默认 offer，未知 SKU 不凭区间构造。
任务删除、商品删除要覆盖新关联记录，防止孤儿数据；同一外部 ID 跨任务仍隔离。
关闭新视频能力不会影响原有图片功能；已升级数据库不承诺直接降级可写，完整回退采用备份数据库与旧镜像成对恢复。
保留本机已忽略的 Windows 快捷脚本、私人文档和 .env；不提交凭据、真实数据库、视频缓存和个人资料。
当前仅提交设计到本地专用分支；实施前审查远程变化，实施完成不擅自更新 main、release、Tag 或 GHCR。

## 8. 验收与交付

每阶段：先失败测试 → 最小实现 → 单测／集成测试 → 独立代码审查 → 修复 → 再验证；再进入下一阶段。

必要验收用例：
1. 配件 99、128GB 1200、256GB 1500：目标 256GB 使用 1500，预算筛选与历史比较正确，绝不拿 99 评分。
2. 占位价 1 元、明确非售价或需询价：待确认、无性价比／本批最优，开关与去重符合约定。
3. 冲突价、选项售罄、SKU 身份变更、详情失败、组合超限不被静默视为已核验；人工报价不会被自动覆盖。
4. 同一规格降价才产生降价事件；不同规格切换、人工报价过期、条件变化均不冒充降价。
5. 图片、纯视频、混合媒体、样品视频、过期链接、超大小、超时、缺 FFmpeg、SSRF／路径穿越均有回归用例。
6. 旧库迁移两遍结果一致，任务／历史／快照／通知不丢失；备份恢复演练通过。
7. Ruff、锁文件检查、全套 pytest、覆盖率不低于现有 80% 门槛；关键新裁决分支需直接覆盖，不能只靠总覆盖率。
8. Docker 构建、SDK 导入、FFmpeg 检测、独立数据库启动、healthz、表单／详情／提醒预览与 noVNC 模式检查通过。
9. 提供性能基线与改后对比，未运行项和受外部环境限制的项如实列出，不以合成样本代替真实平台验证。

真实平台适配需要合法可访问的多 SKU、询价、纯视频／混合媒体代表样本；采集夹具必须脱敏。
若缺真实样本可完成领域模型、规则与夹具测试，但不能将真实 SKU 自动提取／视频覆盖宣称完成；
相关能力保持实验性／待验证并明确列为交付限制，不自动启用或发布稳定版。

## 9. 待批准的提议与实施者可决定事项

待用户随设计一并批准：待询价站内保留但外部提醒默认关闭；人工报价默认 7 天；视频抽帧可选且默认关闭；
分阶段完成三个阶段，真实样本验证不足时明确标为限制而非伪造兼容结论。
以上默认值均为助手提议，不表示用户此前逐项确认。
同样待批准的裁决：有效人工报价优先但来源切换不算降价；新鲜度过期暂停推荐、保留报价；
最低品相分大于 0 时未核验不得进入正常推荐。实施计划必须显式覆盖这些变化与回归测试。

实施者可决定：内部模块命名、索引具体形式、帧去重算法及可维护的采样细节、测试工具与基准夹具组织；
不得改变不自动联系卖家、不用未知价排名、不触碰真实数据、不默默扩大资源预算等边界。
